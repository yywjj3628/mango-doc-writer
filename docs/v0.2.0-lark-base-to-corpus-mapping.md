# v0.2.0 飞书 Base → VPS Corpus 映射规范

> **版本**: v0.2.0  
> **阶段**: Stage A0 — 设计落地  
> **原则**: 飞书 Base 是 staging，VPS 是最终生产入库环境。VPS 只消费 Base 中 cleaned 记录，不直接抓飞书云盘原始材料。

---

## 1. 定位与分工

| 角色 | 职责 |
|------|------|
| **飞书 Base** | staging 层，存储清洗后语料，一篇一行。不是最终库。 |
| **飞书 OpenClaw** | 脏活执行者：抓取、清洗、拆分、写入 Base。 |
| **VPS OpenClaw** | 生产侧：只读 Base cleaned 记录，落盘到 VPS 本地 corpus，做审计、入 Qdrant、规则萃取。 |

**硬性约束**:
- VPS **不**直接读取飞书云盘原始材料（PDF/Word/云文档）。
- VPS **只**通过飞书 Base API 读取已清洗记录。
- VPS **不**修改 Base 中的记录。
- Base 中的 clean_status 由飞书 OpenClaw 写入，VPS 只读取。

## 2. 当前已知 Base 字段

v0.1.x 阶段，Base 字段较简单：

| `时间` | 日期 | 发布日期 |
| `链接` | URL | 原文链接（公众号/网页） |

| `备注` | `topic`（启发式） | 如果备注包含主题关键词，提取为 topic |
| `clean_status` | `clean_status` | 直接映射 |
| `split_status` | `split_status` | 直接映射 |
| `needs_manual_review` | `needs_manual_review` | 复选框 → boolean |
| `manual_review_reason` | `manual_review_reason` | 直接映射 |
| `source_type` | `source_type` | 直接映射 |
| `issue_no` | `issue_no` | 数字 |
| `total_issue_no` | `total_issue_no` | 数字 |
| `issue_date` | `issue_date` | 日期 → ISO 8601 |
| `tags` | `tags` | 多选 → string[] |
| `doc_type` | `doc_type` | 单选 → string |
| `raw_file_token` | `audit_warnings`（追溯用） | 写入警告列表，供审计追溯 |
| `cleaner` | （不入 metadata） | 用于 Base 侧追溯 |
| `cleaned_at` | `extracted_at` | 日期 → ISO 8601 |

## 5. source_type 推断规则

当 Base **没有** `source_type` 字段时（bootstrap 模式），VPS 脚本按以下启发式推断：

| 条件 | source_type |
|------|------------|
| `来源` 包含 "司情" 或 `备注` 包含 "电广传媒司情" | `weekly_siqing` |
| `来源` 包含 "芒果日志" 或 `链接` 包含 "mp.weixin.qq.com" | `mango_rizhi` |
| `来源` 包含 "飞书" 或 `raw_file_token` 非空 | `feishu_doc` |
| `链接` 以 `http` 开头且非微信 | `web` |
| 以上均不匹配 | `manual` |

## 6. 过滤规则

### 6.1 Strict 模式（推荐生产使用）

**只同步**满足以下所有条件的记录：

1. `clean_status` == `"cleaned"`（必须有此字段）
2. `标题` 非空
3. `正文` 非空

以下情况**跳过**：
- `clean_status` 缺失 → 跳过（不属于 cleaned）
- `clean_status` != `"cleaned"` → 跳过
- `clean_status` == `"rejected"` → 跳过

### 6.2 Bootstrap 模式（过渡期使用）

当 Base **还没有** `clean_status` 字段时：

**允许同步**满足以下所有条件的记录：

1. `标题` 非空
2. `正文` 非空
3. `clean_status` 字段**不存在**（旧表兼容）

**必须**在 metadata 中添加审计警告：

```json
"audit_warnings": ["missing_clean_status_bootstrap"]
```

### 6.3 needs_manual_review 处理

| clean_status | needs_manual_review | 行为 |
|-------------|--------------------|------|
| `cleaned` | `false` | 正常同步，audit_status = `passed` |
| `cleaned` | `true` | 同步落盘，但 audit_status = `review_required`，audit_warnings 含 `"needs_manual_review"` |
| `cleaned` | `true` + reason | 同上，reason 写入 manual_review_reason |

**needs_manual_review 的记录可以落盘到 VPS corpus，但不应进入正式 RAG/Qdrant，除非后续人工确认后手动修改 metadata。**

## 7. 缺字段 Fallback 策略

| 缺失字段 | Fallback | 审计影响 |
|---------|----------|---------|
| `标题` | ❌ fatal — 不同步 | 无（直接跳过） |
| `正文` | ❌ fatal — 不同步 | 无（直接跳过） |
| `时间` | `publish_date = "unknown"` | ⚠️ `missing_publish_date` |
| `来源` | `source = "unknown"` | ⚠️ `missing_source` |
| `概述` | `summary = ""` | 无警告（可选字段） |
| `链接` | 不阻塞（PDF-derived 司情通常无链接） | 无警告 |
| `clean_status` | bootstrap 模式才允许缺失 | ⚠️ `missing_clean_status_bootstrap` |
| `source_type` | 按 §5 启发式推断 | ⚠️ `source_type_inferred` |
| `issue_no` | `null` | 无警告（可选字段） |
| `tags` | `[]` | 无警告（可选字段） |

## 8. 事实安全策略

**Base 中没有任何字段可以赋予事实安全授权。**

- `is_fact_safe` 在 VPS 侧固定为 `false`，不从 Base 映射。
- 即使 Base 中有类似字段，VPS 也**忽略**，不信任 staging 层的标记。
- 事实安全授权必须通过 VPS 侧独立审计流程确认。
- 审计流程（Stage B+）是唯一可以将 `is_fact_safe` 改为 `true` 的路径。

---

## 9. 来源为 "电广传媒司情" 的特殊处理

当 Base 记录的 `来源` = `"电广传媒司情"` 或类似变体：

| 行为 | 值 |
|------|-----|
| `source_type` | 推断为 `weekly_siqing` |
| `doc_type` | 通常为 `"内部资料"` 或空 |
| `链接` | 通常为空（PDF-derived） |
| `is_fact_safe` | `false`（固定） |
| `rule_candidate_allowed` | `true`（司情是最核心的风格学习来源） |

**司情语料是 mango_style_docs 最核心的来源，但仍然是历史内部材料，默认不可作为事实来源。**

## 10. Base Record ID 追溯

每篇语料 metadata 必须包含以下至少一个飞书追溯字段：

| 字段 | 说明 |
|------|------|
| `lark_base_token` | Base app_token（从脚本参数获取） |
| `lark_table_id` | 数据表 ID（从脚本参数获取） |
| `lark_record_id` | 记录 ID（从 API 返回） |

**三条信息组合即可唯一定位 Base 中的一行记录。**

metadata **不得**包含：
- ❌ access_token
- ❌ API secret
- ❌ 用户隐私密钥
- ✅ `lark_base_token` 是业务标识符（非密钥），允许包含
- ✅ `lark_record_url` 是飞书内部链接，允许包含

## 11. 数据流示意

```
飞书云盘原始材料 (PDF/Word/Doc/网页)
        │
        ▼  飞书 OpenClaw 抓取 + 清洗 + 拆分
        │
飞书 Base (staging)
  ┌─────────────────────────────────┐
  │ 标题 │ 来源 │ 正文 │ clean_status │ ... │
  ├──────┼──────┼──────┼──────────────┼─────┤
  │ rec1 │ ...  │ ...  │ cleaned      │ ... │
  │ rec2 │ ...  │ ...  │ cleaned      │ ... │
  │ rec3 │ ...  │ ...  │ needs_review │ ... │
  │ rec4 │ ...  │ ...  │ raw          │ ... │ ← strict 模式跳过
  └─────────────────────────────────┘
        │
        ▼  VPS OpenClaw 只读同步 (cleaned 记录)
        │
VPS Local Corpus
  corpus/mango_style_docs/
  ├── cleaned/{doc_id}.md          ← 正文 Markdown
  ├── metadata/{doc_id}.meta.json  ← 完整 metadata
  ├── manifests/manifest.jsonl      ← 索引 manifest
  ├── audits/                      ← 审计报告
  └── rules_candidates/            ← 候选规则
        │
        ▼  后续阶段 (A3/B/C/D)
        │
  ┌── audit ──→ Qdrant ingest ──→ 规则萃取 ──→ candidates/
  │                                              │
  └── 不自动更新正式 references ◄────────────────┘
```
