# mango-doc-writer 用户使用手册

## 这个系统用来做什么

mango-doc-writer 是湖南芒果系文案生产系统，将用户提供的素材/初稿按照芒果系官方文风和公文规范，生成结构化成稿。

核心价值：**规则库决定"能不能这么写"，称谓库决定"应该怎么称呼"，用户素材决定"事实是什么"，RAG 决定"写得像不像芒果系"。**

## 支持的文种

| 文种 | 行文方向 | 示例场景 |
|------|----------|----------|
| 新闻稿 | 对外宣传 | 活动报道、成果发布 |
| 通知 | 下行文 | 布置工作、报送材料 |
| 请示 | 上行文 | 申请预算、请求批准 |
| 报告 | 上行文 | 汇报工作、反映情况 |
| 函 | 平行文 | 商洽事项、协调配合 |
| 总结 | 内部材料 | 阶段性工作回顾 |
| 汇报材料 | 上行文 | 向上级汇报进展 |
| 领导讲话 | 内部材料 | 工作推进会讲话 |
| 会议纪要 | 内部材料 | 会议记录 |
| 通报 | 下行文 | 表彰批评、情况通报 |

## 如何输入初稿

提供一段文字素材，说明你要写什么：

```
请把下面素材写成芒果系新闻稿，风格正式、有传播感。

5月20日，文化科技融合创新活动在马栏山举行。
活动现场发布了三项创新成果，来自湖南广电集团、芒果超媒等单位的代表参加交流。
```

### 建议提供的信息

- **时间**：具体日期或时间段
- **地点**：活动/会议地点
- **人物**：参会人员、领导（如有）
- **事件**：做了什么、发布了什么、决定了什么
- **数据**：金额、数量、比例（如有）
- **机构**：涉及的单位名称

### 不提供会怎样

缺失的信息不会被编造，而是会：
- 使用【待确认】占位符（如主送单位、落款单位）
- 进入 manual_confirmation_fields（需要人工确认后才能正式使用）
- 在 warnings 中提示风险

## 如何指定文种

在初稿中自然表达即可，系统会自动识别：

- "请写一份通知" → 通知
- "整理成会议纪要" → 会议纪要
- "向集团汇报的正式报告" → 报告
- "给合作单位的函" → 函

如果素材内容与指定文种冲突（如写"报告"但内容像请示），系统会检测冲突并提示确认。

## 输出说明

### final_markdown（主输出）

所有文种都会生成 `final_markdown.md`，这是主交付格式。

### DOCX（公文类增强）

以下文种默认同时生成 DOCX：
- 请示、报告、通知、函、通报

以下文种默认只生成 Markdown：
- 新闻稿、领导讲话、汇报材料、总结、会议纪要

非公文类如需 DOCX，传入 `--format docx` 即可。

## 系统不会自动编造的内容

- 领导姓名、职务
- 预算金额、数据指标
- 活动影响范围、社会反响
- 成果名称、获奖情况
- 政策依据、文件编号
- 会议时间、地点、参会人员（未提供时）

## 如何理解【待确认】占位符

`【主送单位待确认】` 表示系统无法确定该信息，需要人工填写后才能正式使用。

这些信息会出现在 `manual_confirmation_fields` 中，标注了：
- 需要确认的字段名
- 为什么需要确认
- 不确认的影响

## 如何使用生成结果

1. 检查 `final_markdown.md` 正文是否符合预期
2. 查看 `manual_confirmation_fields`，逐一确认或填写占位符
3. 查看 `remaining_risks`，了解仍存在的风险
4. 如有 DOCX 需求，检查 `render/final.docx`
5. 确认无误后使用

## 质量检查说明（v0.1.3 新增）

系统会对最终稿做六项质量检查：

1. **事实安全**：检查是否新增了您未提供的事实
2. **文种匹配**：检查标题、结构、格式是否符合文种规范
3. **芒果风格**：检查表达是否符合芒果系气质
4. **逻辑完整**：检查结构是否完整、信息是否交代清楚
5. **语言质量**：检查用词是否准确、凝练、正式
6. **风险控制**：检查称谓、机构、数据、敏感表达是否稳妥

### 质量检查的结果

- **全部达标**：直接输出 final_markdown
- **部分不达标**：系统会自动尝试修一轮或多轮，尽量达到标准
- **修了还不达标**：保留稿件，但会提示您需要人工复核

### 需要您注意的

- 质量分**不是事实真伪保证**——系统无法验证事实的真伪
- 涉及**领导职务、机构名称、日期、金额、数据、政策表述**等仍需您人工核对
- 系统**不能无人值守正式发稿**——最终稿件需要您确认后才能使用
- 质量检查不调用 RAG、不补充外部事实——它只检查已有内容的质量
