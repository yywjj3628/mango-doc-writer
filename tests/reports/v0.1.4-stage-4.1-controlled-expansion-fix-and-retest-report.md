## 3. Quality Gate 根因与修复说明

### 3.1 根因（双重问题）

**问题 A：Prompt 未注入模式阈值**
- quality gate payload 只传了 `quality_rewrite_round` 和 `max_quality_rewrite_rounds`
- 未传 `mode_adjusted_threshold`
- 模型按 prompt 中写死的"默认 threshold = 8"判断
- creative_mimic 的 8.5 在阈值 8 下 borderline，模型返回 overall_pass=None

**问题 B：代码 .get() 陷阱**
- `qg_result.get("overall_pass", False)` — key 存在但值为 None 时返回 None（不是 False）
- `if None` 是 falsy，走到"不达标"分支

### 3.2 修复措施

**Prompt 层**：
1. 删除"默认 threshold = 8"硬编码表述
2. 新增 `{{mode_adjusted_threshold}}` 和 `{{generation_mode}}` 输入变量
3. 明确要求 overall_pass 必须返回 boolean true/false，不允许 null
4. 明确 overall_pass 判断规则：fact_safety ≥ 8 + risk_control ≥ 8 + 其他维度 ≥ mode_adjusted_threshold + 无 P0 风险

**代码层**：
1. `_build_stage_payload()` 中注入 `mode_adjusted_threshold`（使用本地 `_mode_thresholds` dict，避免 MODE_DEFAULT_THRESHOLDS 作用域问题）
2. quality gate payload 中传入 `mode_adjusted_threshold: report.quality_gate_threshold`
3. 新增 deterministic fallback：当 overall_pass=None 时，基于 scores + threshold + strict维度 重新计算
4. fallback 结果写入 `report.quality_gate_pass_computed = True` 便于追踪

### 3.3 额外发现与修复

**official_use_allowed 覆盖问题**：
- draft 阶段模型可能忽略 `{{generation_mode}}` 变量，输出错误的 `generation_mode` 和 `official_use_allowed`
- 原代码在 draft 结果解析时用 `draft_result.get("official_use_allowed")` 覆盖了 report 中正确的值
- 修复：以 input_data.generation_mode 为准，不信任 draft 模型的 official_use_allowed

## 4. Expansion 字段缺失根因与修复说明

### 4.1 根因

1. **模型行为不确定性**：DeepSeek 模型在某些情况下不输出 expansion_report（尤其是空数组 `[]` 而非空对象 `{}`）
2. **Schema 过严**：draft schema 要求 expansion_report 为 object，但模型返回 `[]`（array），触发 schema 验证失败
3. **Prompt 缺乏强制提醒**：未在输出要求中明确标注 expansion 字段为必填

### 4.2 修复措施

**Schema 层**：
- expansion_report type 从 `"object"` 改为 `["object", "array"]`，允许空数组

**Prompt 层**：
- 04-draft.md 新增 v0.1.4 强制字段提醒（generation_mode、official_use_allowed、expansion_report、draft_disclaimer）
- 05-review.md 新增 expansion_review 强制字段提醒
- 明确告知：如果字段缺失，Pipeline 会自动补充 fallback 并标记人工复核

**代码层**：
- expansion_report 为空数组或空对象时，assisted_expansion/creative_mimic 模式触发 fallback
- fallback 包含 `missing=True, warning=..., manual_review_required=True`
- draft_disclaimer 缺失时 creative_mimic 模式自动补充系统默认免责声明
- expansion_review 缺失时 expansion 模式触发 fallback

**关键发现**：阶段 4 中 review 没有标记任何 unsafe_fabrication，但阶段 4.1 中 review 正确识别了"参赛作品涵盖AI编剧、AI视觉生成、智能剪辑等领域"为用户未提供的虚构内容。这说明 review 的扩写安全审查能力是有效的，之前阶段 4 的运行可能是模型随机波动。

### 5.3 审查内容详情

review 识别的不安全扩写：
```json
{
  "unsafe_fabrication": [{
    "text": "参赛作品涵盖AI编剧、AI视觉生成、智能剪辑等领域",
    "reason": "用户素材未提供任何参赛作品具体领域，属于编造成果技术细节"
  }],
  "confirmation_required": [{
    "text": "从剧本生成、拍摄调度到后期制作",
    "reason": "对'全流程'的具体环节描述，需人工确认是否准确"
  }]
}
```

**结论**：review 的扩写安全审查正常工作，pipeline 的 unsafe_expansion_detected 标记和 human_review_required 强制机制有效。
