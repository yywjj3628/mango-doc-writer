## 一、J2.6C-04 路由优先级错误根因

**问题**：style_domain=dianguang_siqing 但主库仍为 jiuzhirun_docs

**根因**：style_domain 未传递到 rag_client

| 环节 | style_domain 状态 |
|------|-------------------|
| run_gray.py | ✅ 有（命令行参数） |
| input JSON | ✅ 有（"style_domain": "dianguang_siqing"） |
| input_parser.py | ❌ 未提取 style_domain |
| plan_result | ❌ 无 style_domain 字段 |
| rag_client._is_jiuzhirun_writing_task | ❌ 检查 plan_result.get("style_domain") 为空 |

**结论**：style_domain 在 input_parser → plan_result 环节丢失，导致 _is_jiuzhirun_writing_task 无法判断风格域，错误放行 jiuzhirun_docs 路由。

**修复方案**：将 style_domain 从 input_data 传递到 rag_client，或在 plan_result 中包含 style_domain。

## 二、J2.6C-02 文种映射错误根因

**问题**：理论学习发言被写成普通领导部署讲话

**根因**：理论学习发言无独立文种规则

| 环节 | 状态 |
|------|------|
| classify.schema.json | ❌ 无"理论学习发言"枚举 |
| 01-classify.md | ❌ 无"理论学习发言"文种说明 |
| doc-type-rules.md | ❌ 无"理论学习发言"规则 |
| classify 输出 | → "领导讲话" |
| draft 阶段 | → 按"领导讲话"规则生成 |

**结论**：理论学习发言被 classify 映射为"领导讲话"，draft 阶段按普通领导讲话规则生成，导致语气和结构错误。

**修复方案**：
- 方案 A：在"领导讲话"下增加 subtype=speech_context 约束
- 方案 B：新增"理论学习发言"独立文种（推荐）

## 三、J2.6C-03 语料不足 fallback 分析

**问题**：普通领导讲话语料不足，未安全 fallback

**根因**：jiuzhirun_docs 中无顾懿普通讲话语料

| 检查项 | 结果 |
|--------|------|
| 是否排除理论学习发言 | ✅ filter 排除 not_for=true |
| 是否排除 reference_only | ✅ filter 排除 reference_only |
| 过滤后剩余材料 | 经营月报、总结、党建、纪检、意识形态（非讲话类） |
| 是否提示语料不足 | ❌ 未提示 |
| 是否 fallback 到 mango_style_docs | ❌ 未 fallback |

**结论**：filter 正确排除了理论学习发言，但剩余材料不足以支撑普通讲话，系统未提示语料不足。

**修复方案**：当 jiuzhirun_docs 过滤后结果不足时，记录"专项语料不足"并 fallback 到 mango_style_docs。

## 四、J2.6C-01 月报规则缺口

**问题**：经营月报使用"汇报材料"规则，结构和篇幅不符合实际

**根因**：无独立"经营月报"文种规则

| 检查项 | 结果 |
|--------|------|
| classify 输出 | 汇报材料 |
| doc-type-rules.md | 无"经营月报"规则 |
| 生成结构 | 通用汇报材料结构 |

**结论**：经营月报被归类为"汇报材料"，使用通用汇报结构，不符合实际月报格式。

**修复方案**：建立独立"经营月报"文种规则，参考历史月报固定结构。

## 五、感叹号和语气问题

**J2.6C-02、J2.6C-03 输出中存在感叹号和口号化表达**

| 问题 | 来源 |
|------|------|
| 感叹号 | 语料中常见 + 模型习惯 |
| "让我们""一定能够" | 模型生成习惯 |

**修复方案**：在正式材料 prompt 中增加语气规则——原则上使用句号，非必要不用感叹号，避免口号式结尾。
