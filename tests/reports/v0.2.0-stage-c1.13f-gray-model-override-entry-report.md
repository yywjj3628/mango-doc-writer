## 一、修改内容

### 新增 `--model` 参数

```bash
--model deepseek-v4-pro    # 临时用 pro
--model deepseek-v4-flash  # 临时用 flash
# 不传则使用 .env 默认配置
```

### 环境变量处理

- 保存原始 `DEEPSEEK_MODEL`
- 运行前设置 `os.environ["DEEPSEEK_MODEL"] = args.model`
- 子进程继承该环境
- `finally` 中恢复原始值（无则删除，有则还原）

### 灰度记录新增字段

- `requested_model` / `effective_model`
- `model_override_enabled`
- `elapsed_seconds`

## 二、验证结果

| 指标 | Test 1 flash | Test 2 pro |
|------|-------------|-----------|
| requested_model | default | deepseek-v4-pro |
| model_override_enabled | ❌ | ✅ |
| Pipeline | success | success |
| QG | pass | pass |
| elapsed | **216s** | **666s** |
| actual_word_count | **639** | **537** |
| actual_paragraph | 7 | 6 |
| length_under | ✅ 否 | ⚠️ 是 |
| 事实编造 | 无 | 无 |

### 关键发现

**pro 比 flash 更短更慢！**
- flash：639 字 / 216s
- pro：537 字 / 666s（3x 慢，字数更少）

**原因推测**：
- pro 模型更"谨慎"，倾向于精炼表达
- flash 模型反而更"开放"，愿意展开内容
- 在当前 prompt 约束下，flash 的长文表现优于 pro

## 四、结论

### A. ✅ --model 灰度入口可用，可用于后续小样本模型对比

但 **pro 不是长文的银弹** — 在当前测试中 flash 表现反而更好。

**建议**：
- 不建议默认切 pro
- 如果需要更长输出，优先优化 prompt 和 content_type 路由
- pro 可以作为特定场景的备选（如需要更高语言质量时），但不作为长文解决方案
- 后续进入 metadata-aware RAG rerank 优化
