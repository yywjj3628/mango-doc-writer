## 4. 脚本能力

`scripts/corpus/build_corpus_from_base_records.py`

### 输入/输出
- 输入: `--fixture` (JSON 文件)
- 输出: `{output-root}/cleaned/*.md` + `metadata/*.meta.json` + `manifests/manifest-v0.2.0.jsonl`

### 命令行参数
| 参数 | 说明 |
|------|------|
| `--fixture` | 必填，fixture JSON 路径 |
| `--output-root` | 必填，输出根目录 |
| `--strict-cleaned-only` | 只同步 clean_status=cleaned |
| `--bootstrap-missing-clean-status` | 允许缺 clean_status |
| `--limit` | 最大处理数（0=不限） |
| `--dry-run` | 预览模式，不写文件 |

### 核心逻辑
1. 读取 fixture JSON，提取 `_base_token` / `_table_id` / `_view_id` 元数据
2. 遍历 records，按 A0 mapping 文档转换为标准 metadata
3. `should_process()` 根据 strict/bootstrap 模式过滤
4. 生成稳定 doc_id（SHA-256 前 8 位）
5. 写入 Markdown（含 front matter）+ .meta.json + manifest.jsonl
6. 输出统计摘要

## 5. doc_id 规则

**格式**: `{source_type}_{publish_date}_{sha8}`

**输入**: `source_type + title + publish_date + lark_record_id`

**示例**:
- `weekly_siqing_2025-03-17_a3021ba5`
- `mango_rizhi_2024-10-21_1c6b42f3`
- `weekly_siqing_2024-09-26_03ed0935`

**稳定性验证**: ✅ 同一 fixture 重跑两次，输出文件名完全一致。

## 10. 已知限制

1. **返回码**: 脚本在有任何 skip 时返回 exit=1，对 CI 可能造成误判，后续可改为仅在 fatal error 时返回非零。
2. **source_type 推断**: bootstrap 模式下依赖 source 字段启发式推断，可能不够精确。
3. **时间戳**: fixture 中的时间戳为硬编码毫秒值，与真实飞书 API 返回格式一致。
4. **Base 字段**: 脚本硬编码了字段名（标题/正文/时间等），如果飞书 Base 实际字段名不同需调整映射配置。
5. **limit**: limit 作用于处理数而非读取数，跳过的记录不计入 limit。
