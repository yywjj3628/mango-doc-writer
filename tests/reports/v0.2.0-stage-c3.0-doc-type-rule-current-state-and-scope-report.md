## 三、会议新闻 vs 会议纪要当前边界评估

**当前状态：**
- doc-type-rules.md 有"会议纪要"规则（L660），无"会议新闻"规则
- run_gray.py 有"会议纪要"，无"会议新闻"
- prompts 中"新闻稿"可覆盖会议新闻，但无专门区分

**边界问题：**
- 会议新闻：对会议进行新闻报道，侧重传播性、亮点、意义
- 会议纪要：记录会议议定事项，侧重决议、责任分工、时间节点
- 当前无明确规则区分，容易混淆

## 五、C3 优先处理 4 类文种

### 1. 亮点工作材料

**用途：**
- 子公司亮点工作
- 项目亮点
- 阶段成效材料
- 内部汇报前的素材整理

**候选结构：**
```
背景 → 主要亮点 → 具体举措 → 阶段成效 → 经验启示 → 下一步计划
```

### 2. 宣传推文

**用途：**
- 芒果公众号风格
- 活动传播
- 品牌活动
- 青年传播
- 文旅活动

**候选结构：**
```
传播性标题 → 活动导语 → 现场/亮点 → 主体价值 → 意义提升 → 行动/展望
```

### 3. 工作方案

**用途：**
- 内部推进方案
- AI应用方案
- 项目推进方案
- 活动执行方案

**候选结构：**
```
背景依据 → 总体目标 → 重点任务 → 责任分工 → 时间安排 → 保障措施
```

### 4. 会议新闻 vs 会议纪要边界

**目标：**
- 明确"会议新闻"是对会议进行新闻报道
- 明确"会议纪要"是记录会议议定事项
- 避免把会议新闻误判为会议纪要
- 避免新闻稿写成纪要口吻

## 六、C3 doc_type_rule candidate schema 补充建议

在 C2.1 schema 基础上补充：

| 字段 | 说明 |
|------|------|
| applicable_style_domain | 适用风格域（如 dianguang_siqing / mango_official_account） |
| applicable_content_type | 适用内容题材 |
| optional_elements | 可选元素（非必须但推荐） |
| expansion_guidance | 扩写指导（如何展开内容） |
| fact_safety_boundary | 事实安全边界（哪些必须有事实支撑） |
| confusion_with | 容易混淆的文种 |
| distinction_rule | 区分规则 |
