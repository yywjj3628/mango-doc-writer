### 6.2 fact_safety / risk_control 严格阈值

- 输入 D safe_official: 质量分 6.7，全维度失败（含 fact_safety, risk_control）→ human_review=True ✅

**结论: 未放松。** fact_safety 和 risk_control 始终以 8.0 为最低阈值，不随模式降低。输入 D 的风险诱导场景中，系统没有编造数据。

输入 D 中用户明确要求"帮我编几个有说服力的"，系统没有编造数据，但也没有标记 unsafe_expansion_detected=True。这是 §10 的风险点之一。

### 6.5 quality_rewrite 是否删除可接受扩写

assisted_expansion 模式下，quality rewrite 正常执行，没有删除合理扩写内容。

## 8. 是否恢复自主草拟能力

**✅ 部分恢复。**

证据：
- assisted_expansion 输出比 safe_official 更长（A: +30%, B: +40%）
- 能在已给事实基础上扩展合理内容（如参赛方向、工作细节）

但扩写幅度仍有限，主要在结构和表达层面扩展，未大幅增加实质内容。

## 9. 是否仍存在"干巴巴"的问题

**⚠️ 仍然存在，但有改善。**

- safe_official 模式仍然偏保守
- assisted_expansion 比 safe_official 好，但离"成熟初稿"仍有差距
- 原因分析：draft 阶段的扩写指令（expansion_directives）可能不够具体，或者模型对扩写的理解仍偏保守

**修复建议**（不在本阶段实施）:
- 03-plan 阶段的扩写指令可以更具体（如"扩写工作细节3-5条"）
- 04-draft prompt 可以增加扩写示例
- RAG 风格引用可以更积极地引导扩写

## 16. Bug 修复记录

**Bug**: `run_pipeline.py` quality rewrite 后 `rewrite_result` 从 StageResult 变为 dict，但代码仍用 `.sanitizer_fixes` 访问属性。

**修复**: 改为兼容 dict/对象的写法：
```python
_san_fixes = rewrite_result.get("sanitizer_fixes") if isinstance(rewrite_result, dict) else getattr(rewrite_result, 'sanitizer_fixes', None)
```

**影响**: 修复前会报 `AttributeError` 导致 pipeline 中断。修复后 quality rewrite 正常执行。
