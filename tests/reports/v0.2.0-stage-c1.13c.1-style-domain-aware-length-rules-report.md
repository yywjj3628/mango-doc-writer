## 一、C1.13C 过度拉长问题修正

C1.13C 对所有文体统一拉长（司情新闻稿 standard=700-1000），不符合真实语料习惯。修正后：

| style_domain | 文体 | C1.13C standard | C1.13C.1 standard |
|-------------|------|----------------|-------------------|
| dianguang_siqing | 普通新闻稿 | 700-1000 | **300-600** |
| dianguang_siqing | 活动/文旅/获奖 | 700-1000 | **400-700** |
| dianguang_siqing | 亮点工作材料 | 800-1200 | **600-900** |
| dianguang_siqing | 领导讲话 | 1200-1800 | 1200-1800（不变） |
| dianguang_siqing | 汇报材料 | 1000-1500 | 1000-1500（不变） |
| mango_official_account | 活动/宣传推文 | 700-1000 | **800-1200** |
| official_doc | 汇报材料 | 1000-1500 | 1000-1500（不变） |

**核心变化**：司情普通稿不再强行拉长，芒果/公文保持应有篇幅。

## 二、当前篇幅约束在 pipeline 中的位置

| 位置 | 是否控制篇幅 | 说明 |
|------|------------|------|
| run_gray.py requirement | ⚠️ 写入了目标字数 | 但模型当建议不当硬约束 |
| 03-plan prompt | ⚠️ total_word_count_estimate | 只是 estimate，不是下限 |
| 04-draft prompt | ❌ 无强制字数约束 | 只说"遵守 draft_directives" |
| 05-review prompt | ❌ 不检查篇幅 | 只检查事实/文种/称谓 |
| 06-rewrite prompt | ❌ 不检查篇幅 | 只按 review 指令修改 |
| 07-quality-score | ❌ 不检查篇幅 | 只评六维度 |

**结论**：pipeline 中没有任何阶段把篇幅当硬约束。requirement 中的字数目标只是上下文信息，模型可以选择忽略。

## 三、run_gray.py 修正内容

### 3.1 LENGTH_TABLE 改为规则匹配系统

从固定字典改为 `_LENGTH_RULES` 列表，按优先级匹配：
1. `(style, doc, content)` 精确匹配
2. `(style, doc)` 匹配
3. `(style, *)` 风格 fallback
4. `(*, doc)` 文体 fallback
5. `(*, *)` 最终 fallback

### 3.2 内容厚度要求改为 style_domain-aware

- 司情短讯：允许短小精悍，信息密度优先，不凑字
- 司情活动/文旅：保持正式风格，适度展开
- 领导讲话：每项部署至少 2 句展开
- 汇报材料：每节事实描述+分析判断
- 宣传推文：传播感，不写流水账
