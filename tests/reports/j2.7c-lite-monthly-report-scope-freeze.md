# J2.7C-Lite 经营月报框架版能力范围冻结

> 日期：2026-06-05

---

## 一、用户确认的收缩原因

1. 经营月报信息密度很高，很多事实和数据并非用户本人掌握
2. 多数表格由财务在每月实际生成后填写
3. 当前写作系统不负责财务数据采集、表格填报和自动计算
4. 优先跑通经营月报固定框架和分析文字生成能力
5. 表格自动填报、计算公式和完整数据 Schema 后置

---

## 二、第一版支持范围

| # | 能力 | 说明 |
|---|------|------|
| 1 | 识别 output_doc_type=经营月报 | classify 正确识别 |
| 2 | 固定标题和章节顺序 | 按真实月报结构 |
| 3 | 保留核心表格位置和名称 | 使用占位符 |
| 4 | 接收用户已填写表格/摘要/结构化数据 | 不修改用户数据 |
| 5 | 生成月度收入分析 | 根据用户提供的摘要和事实 |
| 6 | 生成累计收入分析 | 根据用户提供的摘要和事实 |
| 7 | 生成资产负债分析 | 根据用户提供的摘要和事实 |
| 8 | 生成现金流分析 | 根据用户提供的摘要和事实 |
| 9 | 整理本月重点工作 | 根据用户提供的事实 |
| 10 | 整理问题与风险 | 仅用户提供时显示 |
| 11 | 整理下月计划 | 根据用户提供的事实 |
| 12 | 数字追溯检查 | 正文数字必须追溯到用户数据 |
| 13 | 缺失数据标记 | "待财务数据补充"，不引用历史 |

## 五、最小输入字段

### 必填

| 字段 | 类型 | 说明 |
|------|------|------|
| reporting_period | string | 报告期间 |
| monthly_work_facts | string | 本月重点工作事实 |
| next_month_plan | string | 下月计划事实 |

### 可选

| 字段 | 类型 | 说明 |
|------|------|------|
| financial_tables_or_summary | string | 已填写表格或表格摘要 |
| monthly_revenue_analysis_facts | string | 月度收入分析事实 |
| cumulative_analysis_facts | string | 累计收入分析事实 |
| balance_sheet_analysis_facts | string | 资产负债分析事实 |
| cash_flow_analysis_facts | string | 现金流分析事实 |
| issues_and_risks | string | 问题与风险 |
| report_date | string | 报告日期 |

### 允许输入形式

- 已填写月报 Word/PDF
- 已填写表格
- 表格摘要
- 用户粘贴的关键数据和事实

### 缺失处理

- 没有财务表格 → 保留表格占位，不生成数字分析
- 没有问题与风险 → 不显示该章节
- 没有分析事实 → 不自行推断

## 六、RAG 使用边界

### jiuzhirun_docs 经营月报语料只用于：

- 学习分析段落表达
- 学习章节衔接
- 学习月报正式语气
- 学习如何描述同比、环比和预算完成情况

### 不得用于：

- 提供本期数据
- 填充空白表格
- 推断本期成果、问题和计划
- 替代财务确认
