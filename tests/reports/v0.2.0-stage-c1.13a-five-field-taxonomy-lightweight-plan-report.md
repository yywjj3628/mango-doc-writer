## 一、当前混乱根因分析

### 1.1 当前系统中各字段的职责

| 字段 | 定义位置 | 当前职责 | 问题 |
|------|---------|---------|------|
| `specified_doc_type` | input_parser.py | 用户指定的最终成稿文种 | 同时承担了风格来源和文体规则两个职责 |
| `generation_mode` | pipeline_types.py | safe_official / assisted_expansion / creative_mimic | 只控制扩写强度，不涉及风格/文体 |
| `requirement` | run_gray.py | 自然语言需求描述 | 包含文种信息，但不结构化 |
| `doc_type`（classify 输出） | classify 阶段 | 最终判定的成稿文种 | 与 specified_doc_type 职责重叠 |
| RAG routing | rag_client.py | 按 doc_type 选 collection 和查询模板 | 把风格来源和文体混在一起 |

### 1.2 混乱根因

**根因 1：doc_type 同时承担了"风格来源"和"最终文体"两个不相关的职责**

当前 `doc_type` 字段同时决定了：
- RAG 从哪个 collection 召回语料（风格来源）
- classify/draft/review 按什么文种规则生成（最终文体）

但"风格来源"和"最终文体"是两个独立维度：
- "电广传媒司情风格"可以写新闻稿、也可以写汇报材料
- "芒果公众号风格"可以写活动稿、也可以写领导讲话
- 新闻稿可以参考芒果风格、也可以参考公文风格

**根因 2：没有 organization_scope，无法区分"写谁"**

当前系统中，"总部动态"只能靠 classify 自动判断，但无法区分：
- 台集团总部动态
- 电广传媒总部动态
- 芒果超媒总部动态
- 子公司动态

用户说"电广传媒司情风格，写久之润亮点工作"，当前系统无法同时表达：
- 风格来源 = 电广传媒司情
- 组织主体 = 久之润

**根因 3：content_type 缺失，无法区分题材**

当前 doc_type 只能表达文体（新闻稿/汇报材料），无法表达题材：
- "文旅经营"和"获奖荣誉"都是新闻稿，但题材不同
- "领导调研"和"会议新闻"都是新闻稿，但内容结构不同
- "活动类"需要特殊处理（活动感、现场感），但当前 taxonomy 不支持

**根因 4：篇幅控制缺失**

当前没有任何机制控制输出篇幅：
- 用户想要 800 字的新闻稿 vs 300 字的简讯，系统无法区分
- assisted_expansion 的扩写深度无法按需调整

### 1.3 混乱示例

| 用户意图 | 当前系统表达 | 问题 |
|---------|------------|------|
| "电广传媒司情风格，写久之润亮点工作" | specified_doc_type="新闻稿" | 风格来源=司情？组织主体=久之润？题材=亮点工作？全部丢失 |
| "芒果公众号风格，写青春芒果派活动" | specified_doc_type="新闻稿" | 风格来源=芒果公众号？题材=活动？无法表达 |
| "公文风格，写文旅业务汇报" | specified_doc_type="汇报材料" | 风格来源=公文？无法同时表达 |
| "写一篇 800 字的新闻稿" | 无控制 | 篇幅无法指定 |

## 二、五字段任务拆解体系

### 2.1 字段定义

| # | 字段 | 英文 | 含义 | 类比 |

| 1 | style_domain | 风格域 | 学谁的风格 / 采用哪类语料 | "穿什么衣服" |

## 四、RAG / 规则库 / prompt 的职责分工

### 4.1 职责分工总览

| 层级 | 职责 | 由哪个字段控制 | 位置 |
|------|------|-------------|------|
| **RAG 召回** | 检索风格参考语料 | style_domain + content_type | rag_client.py |
| **RAG rerank** | 对检索结果加权排序 | style_domain + organization_scope + content_type + output_doc_type | rag_client.py |
| **规则库** | 文种硬约束（格式、禁忌、结构） | output_doc_type | references/doc-type-rules.md |
| **Prompt** | 生成指令（扩写边界、风格要求） | style_domain + content_type + length_mode | prompts/ |
| **Schema** | 输出结构约束 | output_doc_type | schemas/ |

### 4.2 各字段的影响路径

#### style_domain → RAG 召回 + rerank

**影响 RAG collection 选择**：
- `dianguang_siqing` → 优先 mango_style_docs（dianguang_media 子集）
- `mango_official_account` → 优先 mango_style_docs（hunan_mango 子集）
- `official_doc` → 优先 jiuyou_docs
- `business_knowledge` → 优先 jiuyou_docs

**影响 rerank 权重**：
- `dianguang_siqing` → source_family:dianguang_media +1.0, hunan_mango -0.5
- `mango_official_account` → source_family:hunan_mango +2.0, dianguang_media -1.0
- `official_doc` → style_weight:high -1.0（偏好正式风格）

**不影响**：文种规则、输出结构、禁忌内容。

#### organization_scope → 称谓口径 + 领导职务

**影响 org-title-dictionary.yaml 查询**：
- `dianguang_media` → "电广传媒""公司"
- `jiuzhirun` → "久之润""久游网"
- `hunan_broadcast_group` → "湖南广播影视集团""台集团"

**影响领导职务查询**：
- 领导姓名 + organization_scope → 查对应组织的领导职务

**不影响**：RAG 召回、文种规则。

#### content_type → 题材规则 + 检索偏好

**影响题材规则**：
- `culture_tourism` → 允许活动感、允许数据引用
- `honor_award` → 保留正式评价语气
- `leader_research` → 按调研结构组织
- `event_activity` → 允许现场感

**影响 RAG 查询模板**：
- `culture_tourism` → "文旅 芒果 活动 经营"
- `honor_award` → "获奖 荣誉 表彰"
- `leader_research` → "调研 考察 座谈"

**影响 rerank 加权**：
- `culture_tourism` + 素材中有 culture_tourism → bonus +1.0

**不影响**：最终文体结构、称谓口径。

#### output_doc_type → 文种规则 + 结构

**影响 doc-type-rules.md 加载**：
- `新闻稿` → 新闻稿规则（导语→主体→结尾）
- `领导讲话` → 讲话稿规则（开场→部署→号召）
- `汇报材料` → 汇报规则（基本情况→成效→问题→计划）

**影响 schema 选择**：
- 不同文种可能有不同的 schema 约束

**不影响**：RAG 召回、称谓口径、篇幅。

#### length_mode → 篇幅 + 扩写深度

**影响 requirement 中的篇幅指令**：
- `short` → "控制在 200-400 字"
- `standard` → "500-800 字左右"
- `long` → "1000-2000 字，需要充分展开"
- `custom` → "目标 {target_words} 字"

**影响扩写深度**：
- `short` → 只保留核心事实，不扩写
- `standard` → 允许结构扩展和表达润色
- `long` → 允许深度扩写、补充背景、展开论述

**不影响**：RAG 召回、文种规则、称谓口径。

### 4.3 规则库 vs RAG 的边界

| 内容 | 来源 | 原因 |
|------|------|------|
| 文种结构（导语/主体/结尾） | rules（doc-type-rules.md） | 硬约束，不能靠 RAG 猜 |
| 文种禁忌（请示不得一文多事） | rules | 硬约束 |
| 称谓口径（"电广传媒"还是"公司"） | rules（org-title-dictionary.yaml） | 硬约束 |
| 领导职务 | rules | 硬约束 |
| 表达风格（芒果系修辞） | RAG | 软参考 |
| 句式节奏 | RAG | 软参考 |
| 标题风格 | RAG + rules | RAG 给参考，rules 给格式 |
| 段落衔接 | RAG | 软参考 |

**核心原则**：RAG 只提供"怎么写"的参考，rules 提供"能不能写"的约束。

## 五、轻量改造边界

### 5.1 C1.13B：run_gray.py 五字段入口实现

**改动文件**：
- `scripts/run_gray.py`：增加 5 个 CLI 参数 + 临时 JSON 写入

**改动内容**：
```
--style-domain     风格域（默认 auto）
--organization-scope 组织范围（默认 auto）
--content-type     内容类型（默认 auto）
--doc-type         输出文体（默认 新闻稿，已有）
--length           篇幅模式（默认 standard）
--target-words     自定义目标字数（length=custom 时使用）
```

**灰度记录新增字段**：
- requested_style_domain / style_domain_source
- requested_organization_scope / organization_scope_source
- requested_content_type / content_type_source
- requested_output_doc_type / output_doc_type_source
- requested_length_mode
- actual_word_count

**人话调用方式**：
