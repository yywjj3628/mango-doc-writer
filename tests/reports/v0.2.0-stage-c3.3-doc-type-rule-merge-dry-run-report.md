## 四、proposed patch 内容摘要

### PATCH 1：亮点工作材料（新增）

- **结构**：背景 → 亮点/举措 → 成效/价值 → 经验启示 → 下一步
- **短版**：背景 → 亮点 → 成效 → 下一步
- **亮点数量**：1-3 个，根据素材事实决定
- **数据规则**：有数据则保留，无数据可写定性成效，不得编造
- **篇幅**：司情 500-900 字；集团级/专题 1000-1500 字
- **禁止**：流水账、空洞口号、编造数据、编造领导评价、为凑亮点强行拆分

### PATCH 2：宣传推文（新增）

- **style_domain 分层**：
  - dianguang_siqing：克制正式，500-800 字
  - mango_official_account：传播感强，800-1200 字
- **结构**：传播性标题 → 活动导语 → 现场或亮点 → 主体价值 → 意义提升 → 行动/展望
- **禁止**：纯公文语调、无传播点平铺、过度营销、编造现场/嘉宾/数据

### PATCH 3：工作方案（新增）

- **结构**：背景依据 → 总体目标 → 重点任务 → 责任分工 → 时间安排 → 保障措施
- **篇幅三档**：简版 800-1200；标准 1500-2500；复杂 3000+
- **缺失信息处理**：标注"待确认"，不得编造
- **禁止**：空泛目标、无责任人任务、无时间节点、纯口号

### PATCH 4：会议新闻（新增）

- **结构**：标题 → 导语 → 会议主题 → 主要内容/部署要求 → 参会或发言要点 → 意义/下一步
- **领导讲话**：可选元素，有则保留无则不编造
- **输出目的判断**：用户要求写新闻稿时，即使有议定事项也写新闻
- **篇幅**：司情 400-800；集团级/公众号 800-1200
- **禁止**：逐条罗列议程、纪要口吻、决议清单、责任分工表

### PATCH 5：会议纪要边界补充（修改现有）

- **核心原则**：看输出目的，不只看关键词
- **四条判断规则**：用户要求决定文种，素材内容服务于文种
- **双向禁止**：纪要中禁止传播性元素，新闻中禁止纪要式条目

### PATCH 6：附录更新（修改现有）

- 新增 4 组判别规则
