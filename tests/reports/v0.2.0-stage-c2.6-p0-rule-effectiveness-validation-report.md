## 三、小样本灰度验证

### Test 1：顾懿职务验证

**输入：**
```json
{
  "topic": "久之润AI内容生产专题交流会",
  "facts": [
    "6月5日久之润召开AI内容生产专题交流会",
    "顾懿围绕项目经验、内容生产效率和下一步重点工作作交流发言"
  ],
  "mode": "assisted_expansion"
}
```

**参数：**
- mode: assisted_expansion
- style_domain: dianguang_siqing
- organization_scope: jiuzhirun
- content_type: subsidiary_highlight
- doc_type: 新闻稿
- length: standard
- timeout: 480s

**结果：**
| 指标 | 值 |
|------|-----|
| Pipeline | ✅ success（217s） |
| RAG | ✅ success |
| QG | ❌ fail |
| generation_mode | safe_official |

**输出分析：**
- ❌ **顾懿未出现在输出中**
- 输出使用"久之润（久游网）【待确认主体关系】"
- 存在多处占位符："待确认主体关系"、"待确认组织关系"
- 未编造其他职务 ✅
- 未把顾懿写成电广传媒领导 ✅（因为根本没提到顾懿）

**根因分析：**
输入使用 facts 数组格式，extract 阶段未将"顾懿"识别为 leader。输入格式为：
```json
{"facts": ["顾懿围绕项目经验..."]}
```
而非原始文本格式。extract 模型仅提取了 organization（久之润、久游网），未提取 person（顾懿）。

**结论：** 规则已写入，但输入格式导致 extract 未识别顾懿。需要在输入中使用原始文本格式，或在 facts 中明确标注人名。

## 五、发现的问题

### 5.1 顾懿未被 extract 识别（低风险）

**问题：** 输入使用 facts 数组格式，extract 阶段未将"顾懿"识别为 leader。

**根因：** extract 模型处理 facts 数组时，仅提取 organization，未提取 person。

**建议：**
- 后续测试使用原始文本格式输入（非 facts 数组）
- 或在 facts 中明确标注人名和职务

**影响：** 低。规则已写入 org-title-dictionary.yaml，当 extract 识别到顾懿时，draft 阶段会使用正确职务。

### 5.2 QG 均 fail（已知问题）

**问题：** 两个测试 QG 均 fail。

**根因：** 输入信息不足（facts 过于简略），导致生成内容空洞。

**影响：** 低。与规则生效验证无关，属于 assisted_expansion 模式的已知限制。
