# C2.1 规则候选 Schema 说明文档

> 版本：v0.2.0
> 日期：2026-06-02
> 用途：规范 C2.2+ 规则候选萃取的 JSONL 格式

---

## 一、概述

本 schema 定义了 mango-doc-writer 规则候选的标准格式。后续 C2.2 从语料中萃取规则候选时，每条候选必须符合此 schema。

### 设计原则

1. **统一格式**：所有候选类型使用相同的顶层结构
2. **类型特化**：`value` 字段根据 `candidate_type` 有不同结构
3. **证据导向**：每条候选必须有原始语料证据
4. **人工确认**：支持 `reviewer_decision` 和 `reviewer_note`
5. **可追溯**：保留来源文档、日期、证据计数

---

## 二、顶层结构

```json
{
  "candidate_id": "string (必填)",
  "candidate_type": "string (必填)",
  "key": "string (必填)",
  "value": { ... } (必填),
  "evidence": { ... } (必填),
  "review": { ... } (必填),
  "created_at": "string (必填)"
}
```

### 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| candidate_id | string | ✅ | 唯一 ID，格式：`{type}_{short_hash}` |
| candidate_type | string | ✅ | 候选类型枚举 |
| key | string | ✅ | 主键/名称 |
| value | object | ✅ | 结构化值（格式因类型而异） |
| evidence | object | ✅ | 证据信息 |
| review | object | ✅ | 审核信息 |
| created_at | string | ✅ | 创建时间，ISO 8601 |

### 3.4 doc_type_rule（文种规则）

**用途**：新增文种规则候选

**value 字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| output_doc_type | string | 文种名称 |
| rule_name | string | 规则名称 |
| structure | string | 建议结构 |
| tone | string | 语调要求 |

| forbidden_elements | string[] | 禁止的元素 |
| length_guidance | string | 篇幅建议 |
| example_source | string\|null | 示例来源 |

**预定义文种结构**：

| 文种 | 建议结构 |

| 亮点工作材料 | 背景 → 主要亮点 → 具体举措 → 阶段成效 → 经验启示 → 下一步计划 |
| 宣传推文 | 传播性标题 → 活动导语 → 现场/亮点 → 主体价值 → 意义提升 → 行动/展望 |
| 工作方案 | 背景依据 → 总体目标 → 重点任务 → 责任分工 → 时间安排 → 保障措施 |

## 五、审核字段说明

```json
{
  "confidence": "high",
  "is_time_sensitive": false,
  "needs_manual_review": true,
  "conflict_with_existing": null,
  "suggested_action": "human_confirm",
  "reviewer_decision": null,
  "reviewer_note": null,
  "reviewed_at": null
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| confidence | string | 萃取置信度：high/medium/low |
| is_time_sensitive | boolean | 是否时效敏感 |
| needs_manual_review | boolean | 是否需要人工确认 |
| conflict_with_existing | string\|null | 与现有规则的冲突描述 |
| suggested_action | string | 建议动作 |
| reviewer_decision | string\|null | 人工审核决定 |
| reviewer_note | string\|null | 人工审核备注 |
| reviewed_at | string\|null | 审核时间 |

### suggested_action 枚举

| 值 | 含义 |
|----|------|
| auto_import | 直接导入正式规则库 |
| human_confirm | 需人工确认后决定 |
| defer | 暂缓处理 |
| discard | 弃用 |

### reviewer_decision 枚举

| 值 | 含义 |
|----|------|
| approved | 直接采用 |
| modified | 修改后采用 |
| rejected | 弃用 |
| deferred | 暂缓 |

## 六、candidate_id 生成规则

格式：`{type_prefix}_{key_short}_{hash4}`

| candidate_type | type_prefix |
|---------------|-------------|
| leader_title | leader |
| subsidiary_affiliation | sub |
| company_alias | alias |
| doc_type_rule | doctype |
| style_phrase | phrase |
| risk_rule | risk |
| field_hint_rule | hash |

`key_short`：key 的前 4 个字符（中文）或前 8 个字符（英文）

`hash4`：UUID 前 4 位

示例：`leader_顾懿_a3f2`、`sub_久之润_b7d1`、`doctype_亮点工作材料_d1a5`

## 七、JSONL 文件格式

每行一个 JSON 对象，无外层数组：

```
{"candidate_id":"leader_顾懿_a3f2","candidate_type":"leader_title","key":"顾懿",...}
{"candidate_id":"sub_久之润_b7d1","candidate_type":"subsidiary_affiliation","key":"久之润",...}
```

## 八、人工确认流程

1. 萃取生成 `{stage}-candidates.jsonl`
2. 使用 `c2.1-human-review-template.md/csv` 进行人工复核
3. 填写 `reviewer_decision` 和 `reviewer_note`
4. 根据决定：
   - `approved` → 直接导入正式规则库
   - `modified` → 修改后导入
   - `rejected` → 标记为弃用
   - `deferred` → 保留待后续处理
