## 一、修改内容

### 1. 篇幅规则表增强

从简单的字数范围扩展为"字数 + 段落数 + 结构要求"三维度：

| 文体 | short | standard | long |
|------|-------|----------|------|
| 新闻稿 | 400-600字/3-4段 | 700-1000字/5-7段 | 1200-1500字/7-10段 |
| 领导讲话 | 800-1000字/5-7段 | 1200-1800字/8-12段 | 2000+字/12+段 |
| 汇报材料 | 700-900字/4-5节 | 1000-1500字/5节 | 1800+字/5-7节 |
| 亮点工作材料 | 500-700字/3-4段 | 800-1200字/4-6段 | 1500+字/6-8段 |
| 宣传推文 | 400-600字/3-4段 | 700-1000字/5-7段 | 1200+字/7-9段 |

### 2. 内容厚度要求

每种文体在 requirement 中新增专属内容厚度指令：
- **领导讲话**：每项部署至少2句展开，不能单句化
- **新闻稿**：展开"为什么做、怎么做、有什么亮点、下一步怎么落地"
- **汇报材料**：每节至少事实描述+分析判断，缺数据写"待确认"
- **亮点工作材料**：每个亮点至少2-3句展开
- **宣传推文**：要有传播感，不写流水账

### 3. 灰度记录新增字段

- `expected_word_range` / `expected_min_paragraphs`
- `actual_word_count` / `actual_paragraph_count`
- `length_under_target`（是否达标）
- `length_under_target_reason`（不达标原因）

## 三、根因分析

**为什么 requirement 中写了篇幅要求，模型还是写不长？**

根因不在 run_gray.py，而在 **pipeline 的 04-draft prompt**：

1. **04-draft prompt 中没有强制篇幅约束**：prompt 要求"按 plan_result.sections 生成正文"，但 plan 阶段的 `total_word_count_estimate` 只是建议，不是强制
2. **模型倾向于简洁输出**：DeepSeek v4-flash 在没有明确字数约束时，倾向于输出精炼内容
3. **requirement 是 prompt 的一部分，但不是强制约束**：requirement 写入了临时 JSON，传到 pipeline 后被注入 prompt context，但模型把它当作"建议"而非"硬约束"
4. **rewrite 阶段可能压缩内容**：review/rewrite 可能删除"多余"内容

**真正需要改的地方**：
- 04-draft prompt 中增加"正文不得少于 X 字"的硬约束
- 或 plan 阶段的 `total_word_count_estimate` 从"建议"变为"下限"

但这超出了 C1.13C 的范围（只改 run_gray.py）。
