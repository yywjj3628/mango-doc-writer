## 二、正式文种规则更新清单

### 2.1 新增文种（4 个）

#### ① 亮点工作材料

| 维度 | 规则 |
|------|------|
| 结构 | 标准版：背景 → 亮点/举措 → 成效/价值 → 经验启示 → 下一步；短版：背景 → 亮点 → 成效 → 下一步 |
| 亮点数量 | 1-3 个，根据素材事实决定，不强行凑满 |
| 数据规则 | 有数据则保留，无数据可写定性成效，不得编造 |
| 篇幅 | 司情 500-900 字；集团级/专题 1000-1500 字 |
| 禁止 | 流水账、空洞口号、编造数据、编造领导评价、为凑亮点强行拆分素材 |
| 区分 | vs 总结（全面复盘含问题）、vs 汇报材料（含分析）、vs 新闻稿（面向公众） |

#### ② 宣传推文

| 维度 | 规则 |
|------|------|
| 结构 | 传播性标题 → 活动/事件导语 → 现场或亮点 → 主体价值 → 意义提升 → 行动/展望 |
| style_domain | dianguang_siqing（克制正式，500-800 字）/ mango_official_account（传播感强，800-1200 字） |
| 禁止 | 过度营销、编造现场/嘉宾/数据、把司情稿写成商业软文 |
| 区分 | vs 新闻稿（事实陈述 vs 传播性情感共鸣） |

#### ③ 工作方案

| 维度 | 规则 |
|------|------|
| 结构 | 背景依据 → 总体目标 → 重点任务 → 责任分工 → 时间安排 → 保障措施 |
| 篇幅 | 简版 800-1200；标准 1500-2500；复杂 3000+ |
| 缺失信息 | 缺责任人/时间节点/具体任务时标注"待确认"，不得编造 |
| 禁止 | 空泛目标、无责任人任务、无时间节点、纯口号、写成汇报材料或总结 |
| 区分 | vs 通知（布置当前任务）、vs 汇报材料（向领导汇报）、vs 总结（过去复盘） |

#### ④ 会议新闻

| 维度 | 规则 |
|------|------|
| 结构 | 标题 → 导语 → 会议主题 → 主要内容/部署要求 → 参会或发言要点 → 意义/下一步 |
| 领导讲话 | 可选元素，有则保留，没有不得编造 |
| 篇幅 | 司情 400-800；集团级/公众号 800-1200 |
| 输出目的判断 | 用户要求写新闻稿时，即使素材有议定事项也写新闻不写纪要 |
| 禁止 | 逐条罗列议程、纪要口吻、决议清单、责任分工表 |
| 区分 | vs 会议纪要（报道 vs 记录）、vs 新闻稿（会议场景子类） |

### 2.2 边界补充（1 个）

#### 会议纪要边界补充

| 维度 | 规则 |
|------|------|
| 核心原则 | 看输出目的，不只看关键词 |
| 判断规则 | 用户要求"报道会议/写新闻稿/发司情公众号" → 会议新闻；用户要求"整理纪要/记录议定事项/责任分工/完成时限" → 会议纪要 |
| 素材冲突 | 素材有议定事项但用户要新闻稿 → 写新闻；素材有召开/强调但用户要纪要 → 写纪要 |
| 双向禁止 | 纪要中禁止传播性元素；新闻中禁止纪要式条目 |

### 2.3 附录判别规则扩展

| 维度 | 变化 |
|------|------|
| 原有 | 5 组（请示 vs 报告、通知 vs 新闻稿、函 vs 请示/报告、总结 vs 报告、汇报材料 vs 正式报告） |
| 新增 | 4 组（亮点工作材料 vs 总结/汇报、宣传推文 vs 新闻稿、工作方案 vs 通知/汇报、会议新闻 vs 会议纪要） |
| 扩展后 | 9 组 |
