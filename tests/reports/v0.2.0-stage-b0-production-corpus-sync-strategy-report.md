## 5. 当前 Base Schema 缺口

### 已有字段（7 个）

标题、来源、备注、正文、概述、时间、链接

### 缺失的关键字段（按优先级排序）

| 优先级 | 字段 | 影响 |
|--------|------|------|
| 🔴 P0 | clean_status | 没有 clean_status，strict 模式无法启动，只能用 bootstrap |
| 🟡 P1 | source_type | 启发式推断精度不足（"电广传媒917" → manual 而非 weekly_siqing） |
| 🟡 P1 | needs_manual_review + reason | 无法在 Base 侧标记问题记录 |
| 🟡 P1 | split_status | 无法判断是否拆分 |
| 🟢 P2 | issue_no / total_issue_no / issue_date | 期刊类语料缺少期号信息 |
| 🟢 P2 | cleaned_at | 缺少清洗时间追溯 |
| 🔵 P3 | tags / doc_type / topic | 分类信息缺失，但不阻塞同步 |
| 🔵 P3 | source_url / raw_file_token / cleaner | 追溯信息缺失，但不阻塞同步 |

### 缺口评估

**没有 clean_status 是进入正式生产的唯一硬阻塞。** 其余字段有 fallback，但不建议长期依赖 fallback。

## 6. 是否建议立即全量正式落盘

**❌ 不建议。**

### 原因

1. Base 无 clean_status → strict 模式无法运行
2. bootstrap 模式不适合正式生产（草稿/废弃稿混入风险）
3. source_type 启发式推断精度不足
4. 全量 bootstrap 落盘后再切换 strict 成本更高（需全量重跑）

### 建议路径

1. **飞书 OpenClaw 补 Base 字段**（至少 clean_status + source_type）
2. 回填已有记录的 clean_status
3. VPS strict 模式 dry-run 全量验证
4. 验证通过后启动 Stage B1

## 8. B1/B2/B3 建议边界

| 阶段 | 名称 | 目标 | 约束 |
|------|------|------|------|
| **B1** | 小批量 strict 验证 | 限制 10-20 条，strict-cleaned-only 模式落盘到正式 corpus | audit 必须 PASS；manifest snapshot 保存 |
| **B2** | 全量 dry-run + 同步 | 全量 strict 同步到临时目录 → audit PASS → 同步到正式 corpus | 临时目录和正式目录双重审计 |
