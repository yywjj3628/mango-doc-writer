## 4. lark-cli 调用方式

### 命令

```bash
lark-cli base +record-list \
  --base-token <token> \
  --table-id <table_id> \
  --as user \
  --limit <page_size> \
  --offset <offset>
```

### 返回格式

```json
{
  "ok": true,
  "data": {
    "data": [[row0], [row1], ...],
    "field_id_list": ["fldgFMtR45", ...],
    "record_id_list": ["recvk9bspRbHu6", ...],
    "has_more": true
  }
}
```

### 字段顺序（data 数组索引）

| 索引 | field_id | 字段名 | 类型 |
|------|----------|--------|------|
| 0 | fldgFMtR45 | 时间 | datetime (str) |
| 1 | fld8m0y2Ko | 链接 | text (str) |
| 2 | fldHiWxwlw | 备注 | text (nullable) |
| 3 | fldPqntJEs | 来源 | select (list) |
| 4 | fldQzFNVdH | 标题 | text (str) |
| 5 | flds7zsR4k | 概述 | text (str) |
| 6 | fldxqsxIaG | 正文 | text (str) |

### 字段适配

- **来源**: select 类型返回 list 如 `["电广传媒917"]`，取第一个值
- **时间**: datetime 返回 `"2026-05-19 00:00:00"` 字符串，解析为 `YYYY-MM-DD`
- **备注**: 可为 null（nullable）
- **链接**: 可为 Markdown 格式 `[原文链接](url)`

## 5. Sync 脚本参数

```
--base-token       必填，Base app_token
--table-id         必填，数据表 ID
--view-id          可选，视图 ID
--output-root      必填，输出根目录
--strict-cleaned-only         只同步 clean_status=cleaned
--bootstrap-missing-clean-status  允许缺 clean_status
--limit            最大处理数（0=不限）
--dry-run          预览模式
--as               user/bot（默认 user）
--page-size        分页大小（默认 100）
--save-raw         保存原始 lark-cli 返回到 debug/
```

## 9. 已知限制

1. **lark-cli 不支持 --format json**: 原始输出已是 JSON 格式，直接解析 stdout。
2. **record_id 顺序**: lark-cli +record-list 的 record_id_list 与 data 数组顺序一致，已验证。
3. **来源推断精度**: "电广传媒917" 推断为 manual 而非 weekly_siqing，需后续确认是否需要调整。
4. **分页**: 当前串行分页，大数据量时可能较慢。A2 阶段可接受。
5. **字段顺序依赖**: data 数组索引固定为 KNOWN_FIELDS 定义的顺序，如果 Base 字段顺序变化需更新。
6. **lark-cli 超时**: 设置 60 秒超时，网络差时可能失败。
