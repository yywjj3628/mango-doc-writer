# v0.1.4 阶段 0 设计审计报告 — Controlled Expansion / 增强草拟模式

**日期**: 2026-05-29
**基线版本**: mango-doc-writer v0.1.3
**设计目标**: 新增 generation_mode 开关，区分正式成稿与内部草拟，恢复早期自主草拟能力

---

## 1. 当前 v0.1.3 架构确认

### 六阶段 Pipeline

```
classify → extract → plan → draft → review → rewrite → [quality gate]
```

### 关键约束（当前）

| 约束 | 来源 |
|------|------|
| 不得新增事实 | 04-draft.md draft_policy.no_new_facts |
| RAG 只用于风格 | 04-draft.md draft_policy.rag_used_for_style_only |
| 不得编造领导、数据、时间、地点、金额、职务 | 04-draft.md 核心原则 |
| 不得编造活动成果、政策依据、会议结论 | 04-draft.md 核心原则 |
| 事实必须有 source_text | 02-extract.md |
| review 必须检查事实溯源 | 05-review.md fact_grounding_check |
| quality gate 六维度评分 | 07-quality-score.md |

### 核心问题

v0.1.3 的事实安全规则过于严格，导致：

1. 用户只给少量信息时，输出干巴巴、缺乏"芒果味"
2. 无法模仿芒果体系的战略表述、产品口径、领导讲话句式
3. 无法生成新闻稿常见段落骨架（意义价值、下一步展望等）
4. 无法快速搭架子、出初稿供人工修改

## 2. generation_mode 插入位置建议

### 总体判断

| 组件 | 是否需要改 | 改动程度 | 说明 |
|------|-----------|---------|------|
| PipelineInput | ✅ 必须改 | 小 | 新增 generation_mode 字段 |
| input_parser | ✅ 必须改 | 小 | 解析 generation_mode 参数 |
| 01-classify | ❌ 不建议改 | 无 | classify 不应识别隐含模式，模式由用户显式指定 |
| 02-extract | ❌ 不建议改 | 无 | extract 仍然只抽取用户明确提供的事实 |
| 03-plan | ✅ 必须改 | 中 | 根据模式生成不同的 draft_directives |
| 04-draft | ✅ **主要改动** | 大 | 核心扩写发生点 |
| 05-review | ✅ 必须改 | 中 | 区分"事实错误"和"可接受的表达扩写" |
| 06-rewrite | ✅ 必须改 | 小 | 保留扩写但删除危险虚构 |
| 07-quality-score | ✅ 必须改 | 中 | 按模式调整评分标准 |
| run_pipeline.py | ✅ 必须改 | 中 | 传递 generation_mode 到各阶段 |

### 设计原则

- **classify 不应自动识别模式**：用户必须显式指定 `generation_mode`，避免系统自行判断导致误判
- **extract 不变**：无论什么模式，extract 只抽取用户明确提供的事实
- **plan 负责扩写边界**：根据模式决定哪些内容可以扩写
- **draft 承担主要扩写**：这是核心扩写发生点
- **review 区分事实错误和表达扩写**：不同模式有不同的 review 标准
- **rewrite 保留安全扩写、删除危险虚构**
- **quality gate 按模式调整阈值**

## 3. 三种模式边界表

| 维度 | safe_official | assisted_expansion | creative_mimic |
|------|:---:|:---:|:---:|
| **是否允许表达扩写** | ❌ 不允许 | ✅ 允许 | ✅ 允许（更强） |
| **是否允许结构扩写** | ❌ 不允许 | ✅ 允许 | ✅ 允许（更强） |
| **是否允许战略口径扩写** | ❌ 不允许 | ✅ 允许（通用战略语汇） | ✅ 允许（芒果体系战略语汇） |
| **是否允许产品介绍扩写** | ❌ 不允许 | ✅ 允许（通用产品描述） | ✅ 允许（模仿芒果体系产品表达） |
| **是否允许领导讲话句式扩写** | ❌ 不允许 | ⚠️ 有限允许（通用句式） | ✅ 允许（模仿芒果体系讲话风格） |
| **是否允许补充具体事实** | ❌ 严禁 | ❌ 严禁 | ❌ 严禁 |
| **是否允许使用 RAG** | ✅ 风格参考 | ✅ 风格参考 | ✅ 风格参考（更强模仿） |
| **是否需要标记待确认内容** | ✅ 必须 | ✅ 必须 | ✅ 必须 |
| **是否允许输出正式稿** | ✅ 允许 | ⚠️ 需人工确认 | ❌ 不允许 |
| **quality gate 阈值是否调整** | 不调整（默认 8） | 适当下调（7） | 明显下调（6） |
| **official_use_allowed** | true | true（需确认） | **false** |
| **draft_disclaimer** | 无 | 无 | **必须有** |

### 边界红线（三种模式均不可突破）

1. **不得编造具体领导姓名**（除非用户明确提供）
2. **不得编造具体职务**（除非用户明确提供）
3. **不得编造具体数据**（除非用户明确提供）
4. **不得编造具体金额**（除非用户明确提供）
5. **不得编造具体会议结论**（除非用户明确提供）
6. **不得编造具体时间、地点**（除非用户明确提供）
7. **不得从 RAG 继承具体事实**
8. **不得把推断内容写成确定事实**

### assisted_expansion 允许的扩写范围

| 类型 | 说明 | 示例 |
|------|------|------|
| 表达层扩写 | 芒果体系常见表达、修辞、句式 | "深耕行业""夯实根基""创新驱动" |
| 结构层扩写 | 新闻稿常见段落骨架 | 意义价值段、下一步展望段 |
| 战略口径扩写 | 通用战略语汇（非具体战略判断） | "融入芒果生态""推动产业升级" |
| 产品表达扩写 | 通用产品描述（非具体产品数据） | "持续优化用户体验""拓展业务场景" |
| 领导讲话句式 | 通用领导讲话句式（非具体表态） | "会议指出""会议强调""会议要求" |

### creative_mimic 额外允许的扩写范围

| 类型 | 说明 | 示例 |
|------|------|------|
| 强风格模仿 | 模仿芒果体系文章节奏和语气 | "奋楫扬帆""澎湃动能""赋能升级" |
| 段落骨架 | 更完整的新闻稿/汇报材料骨架 | 自动补充分析段、展望段、总结段 |
| 战略语汇 | 芒果体系特有战略表达 | "马栏山""文化+科技""芒果生态" |

## 4. 推荐新增字段

### 4.1 PipelineInput 新增字段

```python
generation_mode: str = "safe_official"  # "safe_official" | "assisted_expansion" | "creative_mimic"
```

### 4.2 PipelineReport 新增字段

```python
# ─── v0.1.4 generation mode 字段 ────────────────────
generation_mode: str = "safe_official"
expansion_level: str = "none"  # "none" | "style_only" | "style_and_structure"
expansion_report: List[Dict] = field(default_factory=list)
official_use_allowed: bool = True
draft_disclaimer: Optional[str] = None
```

### 4.4 review 输出新增字段

```json
{
  "expansion_safety_check": {
    "status": "pass",
    "summary": "扩写内容均在表达层和结构层，未发现具体事实编造",

```

```json
{
  "generation_mode": "assisted_expansion",
  "mode_adjusted_threshold": 7.0,
  "expansion_quality_score": 8.5,
  "unsafe_expansion_warnings": []
```

### 4.6 字段设计总结

| 字段 | 位置 | safe_official | assisted_expansion | creative_mimic |
|------|------|:---:|:---:|:---:|
| generation_mode | PipelineInput + report | "safe_official" | "assisted_expansion" | "creative_mimic" |
| expansion_level | PipelineReport | "none" | "style_only" 或 "style_and_structure" | "style_and_structure" |
| expansion_report | draft 输出 | [] | 非空 | 非空 |
| official_use_allowed | report | true | true | **false** |
| draft_disclaimer | final_markdown | 无 | 无 | "⚠️ 本文为内部灵感稿..." |
| unsafe_expansion_warnings | review + quality_score | [] | [] 或有 | [] 或有 |
| manual_confirmation_fields | draft + review | 保留原有 | 新增扩写确认项 | 新增扩写确认项 |

## 5. Prompt 修改范围建议

### 修改优先级

| Prompt | 改动程度 | 说明 |
|--------|---------|------|
| 01-classify.md | ❌ 不改 | 模式由用户显式指定，不自动识别 |
| 02-extract.md | ❌ 不改 | extract 只抽取事实，与模式无关 |
| 03-plan.md | ⚠️ 中等 | 新增 generation_mode 条件分支，生成不同的 draft_directives |
| 04-draft.md | 🔴 **主要改动** | 核心扩写逻辑，新增扩写规则和边界 |
| 05-review.md | ⚠️ 中等 | 新增 expansion_safety_check，区分事实错误和表达扩写 |
| 06-rewrite.md | ⚠️ 小 | 新增模式感知：保留安全扩写、标记待确认内容 |
| 07-quality-score.md | ⚠️ 中等 | 按模式调整阈值和评分标准 |

### 5.1 03-plan.md 修改建议

新增条件分支：

```markdown
## generation_mode 感知

如果 generation_mode = "safe_official"：
  - 按 v0.1.3 原有逻辑，不生成扩写指令

如果 generation_mode = "assisted_expansion"：
  - draft_directives 新增 expansion_boundary = "style_and_structure"
  - draft_directives 新增 allowed_expansions 列表
  - draft_directives 新增 forbidden_expansions 列表

如果 generation_mode = "creative_mimic"：
  - draft_directives 新增 expansion_boundary = "full_style_mimic"
  - draft_directives 新增 style_intensity = "high"
  - draft_directives 新增 official_use_allowed = false
```

### 5.2 04-draft.md 修改建议

新增扩写规则章节：

```markdown
## 扩写规则（assisted_expansion / creative_mimic 模式）

### 可以扩写的内容

1. 表达层：芒果体系常见表达、修辞、句式
2. 结构层：新闻稿常见段落骨架（意义价值、下一步展望等）
3. 战略口径：通用战略语汇（"融入芒果生态""推动产业升级"等）
4. 产品表达：通用产品描述（"持续优化用户体验"等）
5. 领导讲话句式：通用句式（"会议指出""会议强调"等）

### 不可以扩写的内容（红线）

1. 具体领导姓名、职务
2. 具体数据、金额
3. 具体时间、地点
4. 具体会议结论
5. 具体政策依据
6. 具体获奖情况
7. 具体活动影响

### 扩写标记要求

所有扩写内容必须在 expansion_report 中记录，包括：
- expansion_type
- description
- examples
- needs_confirmation
```

### 5.3 05-review.md 修改建议

新增 expansion_safety_check：

```markdown
## expansion_safety_check

当 generation_mode != "safe_official" 时，新增此检查：

检查扩写内容是否突破红线：
1. 是否编造具体领导姓名/职务
2. 是否编造具体数据/金额
3. 是否编造具体时间/地点
4. 是否编造具体会议结论

如果发现 unsafe_expansion：
- level = "critical"
- type = "unsafe_expansion"
- rewrite_hint = "删除具体事实编造，改为概括性表述"
```

### 5.4 07-quality-score.md 修改建议

```markdown
## 模式感知评分

当 generation_mode = "safe_official"：
  - 阈值不变（默认 8）
  - fact_safety 权重不变

当 generation_mode = "assisted_expansion"：
  - 阈值下调为 7
  - fact_safety 权重不变（仍为最高）
  - 新增 expansion_quality 维度

当 generation_mode = "creative_mimic"：
  - 阈值下调为 6
  - fact_safety 权重不变
  - 新增 expansion_quality 维度
  - official_use_allowed 必须为 false
```

## 9. 风险点

### P0 风险（必须在阶段 1 解决）

| 风险 | 说明 | 缓解措施 |
|------|------|----------|
| 模式边界模糊 | assisted_expansion 和 creative_mimic 的边界可能混淆 | Prompt 中明确枚举 allowed/forbidden，review 中检查红线 |
| 扩写突破事实红线 | 模型可能在扩写时编造具体事实 | review 新增 expansion_safety_check，quality gate 新增 unsafe_expansion_warnings |
| 旧 case 回归破坏 | 新模式可能影响 safe_official 默认行为 | PipelineInput.generation_mode 默认值为 "safe_official"，所有 Prompt 条件分支以模式为前提 |

### P1 风险（阶段 2-3 解决）

| 风险 | 说明 | 缓解措施 |
|------|------|----------|
| quality gate 阈值不合适 | 7 和 6 可能过高或过低 | 收集实际使用数据后调整 |
| 扩写质量不稳定 | 不同 LLM 对扩写边界的理解不同 | Prompt 中给出明确示例 |
| expansion_report 过长 | 大量扩写时报告可能很长 | 限制报告条目数 |

### P2 风险（监控）

| 风险 | 说明 | 缓解措施 |
|------|------|----------|
| 用户误用模式 | 用户在正式发稿时误用 creative_mimic | official_use_allowed=false 和 disclaimer 提示 |
| Token 消耗增加 | 扩写模式消耗更多 token | 可通过 generation_mode=safe_official 关闭 |
