## 3. audit_manifest.py 能力

### 检查项（27 项）

| 类别 | 检查 |
|------|------|
| **Manifest 完整性** | JSON 合法、doc_id、title、body_md_path、meta_json_path |
| **文件存在性** | body_md_path、meta_json_path 实际存在 |
| **一致性** | manifest vs metadata doc_id、content_hash、char_count |
| **RAG 边界** | rag_usage=style_only、is_fact_safe=false、fact_usage_allowed=false、official_reference_allowed=false |
| **追溯性** | lark_record_id、source、source_type |
| **时间** | publish_date 存在且格式 YYYY-MM-DD |
| **清洗状态** | clean_status、missing_clean_status_bootstrap |
| **人工复核** | needs_manual_review → audit_status=review_required |
| **重复** | doc_id 重复、duplicate_key 重复 |
| **质量** | 正文过短（<80 字符）、目录噪音、过度 bullet |
| **白名单** | source 是否在允许列表 |

### 命令行参数

```
--manifest          必填，manifest.jsonl 路径
--corpus-root       必填，corpus 根目录
--output            必填，报告输出路径
--format            markdown / json
--fail-on-error     有 ERROR 时 exit 1
--min-body-chars    最短正文阈值（默认 80）
```

### 输出格式

- **Markdown**: 含 Summary / Check Results / Errors / Warnings / RAG Boundary / Review Required / Duplicates
- **JSON**: 结构化 issues 数组 + 统计

## 4. 审计级别

| 级别 | 触发条件 | 影响 |
|------|---------|------|
| **ERROR** | JSON 非法、缺必填字段、文件不存在、RAG 边界违规、hash 不匹配 | --fail-on-error 时 exit 1 |
| **WARN** | 缺日期、clean_status 缺失、过短、噪音、白名单外、重复 | 不阻塞 |
| **INFO** | review_required 记录、rule_candidate_only | 信息性 |

## 9. 已知限制

1. **content_hash 计算**: manifest 中的 content_hash 是全文（不含 front matter）的 SHA-256，audit 需 strip front matter 后再计算。
2. **char_count 容差**: 允许 ±10 字符差异（因换行符处理）。
3. **directory_noise**: 正则匹配前 500 字符，可能有误报（如正文恰好含"第X章"关键词）。
4. **source 白名单**: 当前硬编码，未来可改为配置文件。
5. **段落计数**: 以 `\n\n` 分隔，与 metadata 中 paragraph_count 可能因 trailing newline 产生微小差异。
6. **JSON 报告**: 结构简单，可扩展为更详细的 audit artifact。
