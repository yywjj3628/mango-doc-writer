## 三、各规则关键修正详解

### 3.1 亮点工作材料

**核心修正：从"硬性要求"到"弹性适配"**

- **亮点数量**：原"至少3个亮点" → 修正为"1-3个亮点，根据素材事实决定，不强行凑满3个"
- **数据要求**：原"数据支撑"（必须） → 修正为"有数据则保留数据，没有数据不得编造"
- **成效表述**：增加"可写阶段成效、定性成效、工作价值，但必须基于素材"
- **篇幅**：从统一600-900字 → 司情500-900字，集团级/专题材料1000-1500字
- **禁止项新增**："为凑亮点强行拆分素材"

**适用场景**：子公司亮点工作、项目亮点、阶段成效材料、内部汇报前素材整理

### 3.2 宣传推文

**核心修正：按 style_domain 拆分两种风格**

| 维度 | dianguang_siqing | mango_official_account |
|------|------------------|----------------------|
| 语调 | 克制、正式、信息密度高 | 传播感、现场感、节奏感 |
| 边界 | 不能写成营销软文，不过度煽情 | 仍需事实克制，不编造 |
| 篇幅 | 500-800字 | 800-1200字 |
| 禁止 | 夸张口号、编造现场感/嘉宾/数据 | 编造嘉宾/流程/反应/传播数据 |

**共同要求**：传播性标题、活动/事件核心、主体价值、事实边界提示

### 3.3 工作方案

**核心修正：篇幅分层 + 缺失信息处理**

- **篇幅三档**：
  - 简版方案：800-1200字
  - 标准方案：1500-2500字
  - 复杂方案：3000字以上
- **缺失信息处理**：素材缺责任人/时间节点/具体任务时，不得编造，应标注"责任主体待确认""时间节点待确认""具体任务待补充"
- **禁止项新增**："把工作方案写成汇报材料或总结"

### 3.4 会议新闻

**核心修正：领导讲话从必须降为可选**

- **必须元素变化**：原含"领导讲话要点" → 改为"主要内容或部署要求"
- **可选元素新增**：参会人员、主持人、领导讲话要点、发言交流要点
- **输出目的判断**：用户要求写新闻稿时，即使素材有议定事项，也应写会议新闻，只把议定事项作为会议内容
- **篇幅调整**：司情从500-800字放宽至400-800字
- **禁止项新增**："不要把所有会议新闻都写成'某领导强调'"

### 3.5 会议纪要边界补充

**核心修正：从"关键词匹配"到"输出目的判断"**

**判断逻辑升级：**

| 层级 | C3.1 原始 | C3.2 修正后 |
|------|----------|------------|
| 判断依据 | 关键词（议定/决议→纪要；召开/强调→新闻） | 输出目的（用户要求什么就写什么） |
| 素材冲突 | 无处理规则 | 素材有议定事项但用户要新闻稿→写新闻 |
| 边界方向 | 单向 | 双向 |

**四条判断规则：**
1. 用户要求"报道会议""写新闻稿""发司情/公众号" → 会议新闻
2. 用户要求"整理纪要""记录议定事项""明确责任分工/完成时限" → 会议纪要
3. 素材有"议定/决议/同意/责任分工/完成时限"但用户要新闻稿 → 写新闻，议定事项作为内容
4. 素材有"召开/强调/要求"但用户要纪要 → 写纪要

**双向禁止交叉：**
- 会议纪要中禁止：传播性标题、新闻导语、情感表达、意义升华
- 会议新闻中禁止：纪要式条目、责任分工表、决议清单作为主体结构
