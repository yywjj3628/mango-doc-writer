## 四、标准操作流程 SOP

### C2 规则候选标准流程

```
1. 现状审计 (C2.0)
   输入：references/ + prompts/ + pipeline/
   输出：审计报告
   允许改正式规则：否
   人工确认：否

   ↓

2. Schema 定义 (C2.1)
   输入：审计报告
   输出：JSON Schema + 人工确认模板
   允许改正式规则：否
   人工确认：否

   ↓

3. 候选萃取 dry-run (C2.2)
   输入：Schema + 语料 + 用户确认事实
   输出：candidates JSONL
   允许改正式规则：否
   人工确认：否

   ↓

4. 人工确认 (C2.3)
   输入：candidates JSONL + 人工确认表
   输出：reviewed candidates JSONL
   允许改正式规则：否
   人工确认：✅ 必须

   ↓

5. 合并 dry-run (C2.4)
   输入：reviewed candidates + 正式规则文件
   输出：proposed patch
   允许改正式规则：否
   人工确认：否

   ↓

6. 正式应用 patch (C2.5)
   输入：proposed patch
   输出：更新后的正式规则文件
   允许改正式规则：✅
   人工确认：否（基于 C2.3 已确认内容）

   ↓

7. 校验 (C2.5)
   输入：更新后的正式规则文件
   输出：校验结果
   允许改正式规则：否
   人工确认：否

   ↓

8. 小样本生效验证 (C2.6)
   输入：更新后的正式规则文件
   输出：验证报告
   允许改正式规则：否
   人工确认：否

   ↓

9. 收口归档 (C2.8)
   输入：所有阶段报告
   输出：复盘报告 + SOP
   允许改正式规则：否
   人工确认：否
```

### 每步风险点

| 步骤 | 风险点 |
|------|--------|
| 现状审计 | 遗漏现有规则 |
| Schema 定义 | 字段设计不完整 |
| 候选萃取 | 证据不足、遗漏候选 |
| 人工确认 | 用户确认口径不准确 |
| 合并 dry-run | patch 格式错误 |
| 正式应用 | YAML 格式破坏、规则冲突 |
| 校验 | 遗漏检查项 |
| 生效验证 | 输入格式导致规则未触发 |
| 收口归档 | 遗漏遗留问题 |
